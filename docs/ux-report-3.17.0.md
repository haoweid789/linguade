# LinguaDE 3.17.0 长期使用报告（90 天 · 桌面 + 手机 + 线上）

**一句话结论**：这一版最要命的不是内容，是一个词的笔误——`src/store.js:435` 的 `s._questsPerfect` 引用了不在作用域的 `s`，**用户做完当天 3 个每日任务的那一刻起，单词练习页的进度再也不前进，之后每次作答都抛 `ReferenceError`**，而 137 项测试全绿、没有一条覆盖这个状态。往深层看，3.17 把词库从 2000 扩到 5908，却**把产品最值钱的东西（调度算法）用在了一个会自我锁死的预算上**：连续用 90 天后，`buildQueue` 每天给的 20 张卡里**新词恒等于 0**，你从第 3 个月起不再学到任何新单词；同时新增的 3908 条机翻词把人工校订占比从 29% 稀释到 **9.7%**，并让一张 **A2 卡片**的例句变成「Wie weckt man die Begierde einer Frau? / 如何激发女人的性欲？」。综合 **5.5 / 10**：一个月 6.5 分，三个月 **4.0 分**。

**我是谁**：备考 TestDaF 的中国学生，B1 起步，目标 4×4；Windows 笔记本 + Android 手机；单文件版和线上版（<演示服务器IP>）并用；日均 30–50 分钟。

**我怎么测的（以及没测什么）**：`dist/index.html` 用无头 Chromium 真实点击走查（1440×900 / 390×844 / 768×1024），90 天状态用注入的 900 张卡 + 1630 条作答 + 160 条错题 + 90 天打卡模拟；复习债另用纯数学按 `engine.js` 的 HLR 常数独立复算交叉验证；线上版只读浏览，**没有点任何写云端的按钮**（避免污染演示账号快照）。未覆盖：真实麦克风录音（环境无声卡输入）、多设备并发同步、真实真人 90 天。下面每条都标了实测数字或 `文件:行号`。

## 一、时间线

### 第 1 天｜双击就能用，但第一张卡就在考验你

`file://` 打开，**load 133 ms**（本机 SSD，2.26 MB 单文件），零外部请求。10 题诊断走完到报告页约 3 秒。首屏是「今天学什么」，主操作正好 2 个——3.16 承诺的首屏减法**真的做到了**。

但作为一个真人，我第一天就撞到四件事：

1. **第一张新词卡是 `der Ober`（「服务员」，B1，机器对齐 · 待抽检）**。页头同时写着「词库总量 5908 词 · 机器对齐待抽检 5336 条」。也就是说：**我第一天学的第一个词，就是那 90.3% 待抽检里的一个**，而 `Herr Ober` 本身是个偏过时、偏区域性的称呼。产品没有骗我（它标了「待抽检」），但它把最没底气的词递到了最前面。
2. **回不了首页。** 侧栏 18 项里没有「首页」，只有 12 主入口 + 6 更多工具。回「今天学什么」的唯一入口是点左上角 logo——而那是一个 `div.brand` 的 onclick（`src/core/ui.js:288`），**不可 Tab 聚焦**。
3. **诊断错题直接进错题本**（`src/modules/diagnose.js:77`），我第一天侧栏就挂着「错题本 4」。诊断本来是用来定位起点的，不该以「你有 4 道错题待掌握」的形式变成负债。
4. **控制台有 2 条红色报错**：`Fetch API cannot load file:///D:/api/auth/diagnosed` 与 `file:///D:/api/sync`。单文件版没配后端，但代码照样发请求。要说清楚：README 的「`file://` 全域零 JS 错误」指的是**未捕获异常**，这条我复现到 `pageerror = 0`，成立；但 3.16 CHANGELOG 写的是「**0 控制台错误** / 0 外部请求」，这条**不成立**（2 条 console.error）。

另外：诊断的四个选项是 `div.list-item` 而不是 `button`，Tab 两次落在顶栏图标按钮上——**不用鼠标的人第一天就答不完题**。

### 第 1 周｜我把每日任务清空的那一天，单词练习页就不动了

这是我这次用下来最意外的一件事：产品有个很用心的每日任务系统（3 个任务、完成给 XP、还有「任务大师」徽章）。我第一天很积极，把三个任务都清空了——**从那一刻起，「已学 0 / 20」这个计数器再也不动**。按「轻松」，卡片不前进；再按一次，还是不前进。控制台里每一击都是一条 `ReferenceError: s is not defined`。

原因在 `src/store.js:435`：`s._questsPerfect = 1` 引用了一个不在作用域里的 `s`。它被 `logAnswer()` 调用，所以**任务全完成之后的每一次作答都会抛错**；而 `vocab.js:163-165` 是先 `rate()` 后 `logAnswer()`，于是那张卡**已经被评分、已经被写进复习队列**，界面却停在原地——我再点一次，同一个词就被评了第二次。附带地，依赖这个字段的「任务大师」徽章永远解不开。

**137 项测试全绿，没有一条测过「三个任务全完成」这个状态。** 越积极的用户越早撞上——这条我放在最严重的位置。

XP、每日任务、连胜、徽章、留德时间轴、真人录音（离线可听，`data:audio/mpeg` 内联）、错题按类型组卷、词卡报错入口……这个月的体验我给 8 分。3.16 的整改我逐条复核过，**这些是真的修好了**：

### 第 2 个月｜内容包没导入，阅读只有 5 篇

首页那条「单文件版已内置 3 个内容包 · 共 465 条」横幅，**在 90 天里的每一天都在**。它只有「今天不再提示」，点了还会弹 toast 明说「今天不再提示，明天会重新出现」（`src/core/router.js:76,352`）。我第 2 个月才点导入——这期间阅读页一直显示「**共 5 篇可用短文**」。一个把「85 篇阅读包」写进 README 的产品，默认状态给学习者 5 篇，而且横幅的正文塞满了 `CC BY 2.0 FR · audioLicense（已排除 NC）` 这类授权条款，**把法务说明放在了学习者每天第一眼的位置**。

### 第 3 个月｜真正的墙：我不再学任何新词

注入 900 张已学卡（90 天、每天 18 题、正确率 72%）之后，第 91 天早上打开：

```
到期复习 536 个 · 濒临遗忘 877 个 · 今日队列 20 张 · 其中新词 0 张
```

我以为是偶发，于是把保持率阈值从默认 0.90 一路调到 0.70：

```
阈值 0.70 → 濒危 1071 个 · 队列 20 张 · 新词 0 张
```

再用纯数学按 `engine.js` 的同一套常数（`initH=1.0, growOk=1.9, growLate=1.35, dueAt=0.9`）独立复算 90 天，交叉验证同一个结论：

| 场景（每日 20 张 · 正确率 85% · 目标再加 10 新词/天） | 90 天累计新词 | 新词被完全挤出的天数 |
|---|---|---|
| 已学 900 词 · 阈值 0.90（默认） | **0 / 900** | 90 / 90 |
| 已学 900 词 · 阈值 0.80 | 0 / 900 | 90 / 90 |
| 已学 900 词 · 阈值 0.70 | 0 / 900 | 90 / 90 |
| 已学 900 词 · 阈值 0.90 · 每日 60 张 | 0 / 900 | 90 / 90 |
| 已学 900 词 · 阈值 0.90 · 每日 120 张 | 0（但濒危从 886 掉到 193） | 90 / 90 |
| 已学 900 词 · 阈值 0.90 · 每日 200 张 | 233 | 65 / 90 |

**从零基础开始长跑**（每天 20 张、目标 10 新词/天）：

| 坚持天数 | 阈值 0.90 实际学到 | 阈值 0.80 实际学到 | 目标 |
|---|---|---|---|
| 90 天 | **73 词** | 90 词 | 900 |
| 180 天 | 130 词 | 154 词 | 1800 |
| 270 天 | **176 词** | 206 词 | 2700 |

临界点：**已学词超过约 120 个**，新词就开始被挤出；超过 900 个，新词永久为 0。

原因很清楚，而且不是 bug，是**一个没做完的设计**：

- `src/modules/vocab.js:14` 写死 `buildQueue(20)`；设了考试日期时最多 30（`:21-25`）。
- 用户在设置里选的「每日 30 分钟 / 120 分钟」（`dailyMin`）**从不参与队列容量**——它只被用在三个地方：计划文案（`engine.js:374`）、首页一个标签（`router.js:215`）、今日进度条（`analytics.js:21`）。
- 濒危判定是 `p = 2^(-Δ/h) < 0.9`，等价于「距上次练习超过半衰期的 15% 就该复习」。一个新词要连续答对 5 次才爬到 h≈10 天，也就是每 1.5 天要复习一次。900 词的稳态复习需求是**每天数百张**，而队列只给 20 张。
- 最讽刺的是，**算法沙盘自己知道这件事**：`src/modules/sandbox.js:67` 的实验设定写着「每日复习量上限 40 题（超出记为积压放弃）」。学习模块里却没有「积压」这个概念——它只是让 877 个红灯天天亮着。

同屏还有三处文案在透支信任：

1. 推荐卡：「**先复习 536 个到期词 · 约 5–10 分钟**」（`router.js:172` 的 `time` 是写死的字符串，不看 due 数量）。
2. 考试卡：「已启用考试倒排调度（**fitToExam**）：复习间隔自动压缩，**确保考前完成全部词条过一遍**」（`router.js:227`）。距考 31 天、5908 词库、每天 20–30 张——这个「确保」做不到，而且把内部函数名印给了用户。
3. 学情分析：「连续 90 天 · **最长 0 天**」。`streak` 从 `daily` 现场算，`bestStreak` 是独立字段；任何从旧版本导出 JSON 再导入、或从云端恢复快照的用户，都会看到这个自相矛盾的数。

### 期间｜性能与存储：这两项我错怪它了

- 90 天数据（900 卡 + 1630 答题 + 160 错题 + 70 生词 + 各类记录）localStorage 实测 **496 KB**，离 5 MB 配额很远，长跑半年也不会撞墙。
- `buildQueue(20)` 在 5908 词库 × 1391 张卡下 **66–77 ms**，连测 5 次稳定。全库线性扫描没有变成用户可感知的卡顿。
- 结论：**这个产品的长期问题不是性能，是调度预算和内容厚度。**

### 期间｜手机上（390×844）

好消息：**零横向溢出**，抽屉导航正常，遮罩正常。坏消息全在尺寸上：

- 错题本 160 条 → 页面高 **37,657 px**（桌面 23,356 px），**926 个可点元素里 696 个高度 < 40px**（大量 30h×81w 的按钮）。手机上刷错题本等于无限滚动 + 抠像素点按。
- 单词练习页 7 个可点元素里 5 个是 30h×46w；横幅关闭按钮 32h×76w；抽屉菜单项行高 44 和 34 混排。
- 小字在手机上更糟：首页 11.5px 与 10.5px（推荐卡序号「01」）、对话室 11px、听力 11px、句法透视的 SVG 标注 **10px**、沙盘 10.5px、学情分析图表 11px/10px、计划页 11px。3.17 的 CHANGELOG 说「小字全部抬回 12px，`test_small_text_floor_12px` 恢复通过」——**测试确实全绿，承诺确实没守住**：那个测试只量它写死的那几个选择器。

### 期间｜云端同步：长期用户真正的数据风险在这里

我按「手机背词 → 电脑做模考」这个最普通的场景实测（本地起 `uvicorn app.main:app` + 造较新快照）：

1. **同步是整档 last-write-wins，没有任何字段级合并。** 手机 11/3 背了 20 个词并同步；电脑 11/3 晚做了模考再点「同步到学习云」——**手机上那 20 个词的卡片、HLR 状态、XP、错题、生词本全部被云端覆盖，且不可恢复**。3.15 报告提的「静默覆盖」只是变成了「需要你自己判断的覆盖」，合并从来没做。
2. **换设备之后，那唯一的保护伞永久失效。** 冲突提示读的是 `Store.s._snapAt`，而这个字段**只写进 localStorage、不在导出快照里**（`store.js:18`、`:643-645`）。新设备点「从云端恢复」→ 状态里没有 `_snapAt` → 下次同步**永不弹冲突提示，直接整档覆盖云端**。3.16 引以为豪的那条新逻辑，恰好对「换设备」这个最需要同步保护的场景无效。
3. **同步成功后不刷新页面，`_snapAt` 不更新 → 下一次同步必报假冲突**（内容为真的提示）。我复现到：第一次同步成功，紧接着再点一次就弹「云端比本机新，继续会覆盖」。
4. **恢复之后，冲突提示永久失效。** `_snapAt` 会被写进上行快照（`store.js:652`），但 `restoreSnapshot()` 在恢复时把它删掉（`store.js:661`），而冲突判定读的是**本机**的 `_snapAt`（`ui.js:319`）→ 新设备「从云端恢复」之后，下一次同步**永不弹冲突提示，直接整档覆盖云端**。3.16 引以为豪的那条新逻辑，恰好对「换设备」这个最需要同步保护的场景无效。（更正：早前把「API Key 明文上行」列为问题，实测不成立——`snapshot()` 删除整个 `cfg`。）
5. **搬到德国那天，连胜归零。** `dayKey` 用「写入那一刻的时区偏移」把 UTC 转本地日（`store.js:146-149`）。在 +8 打卡 90 天后把系统时区改成 Europe/Berlin，`today()` 会算出一个**未来日期**，`daily` 里全是过去日 → `streak()` 返回 0，首页「隔日未复习」横幅消失，徽章与每日任务同轮集体错。对一个「留德」产品，这是**必然发生**而不是极端场景。系统时钟回拨同样会静默吃掉连胜。
6. **连胜冻结不够用**：每连续 7 天才 +1、上限 3。90 天里第 8 天断一次消耗掉唯一的冻结，之后 82 天零保护。也没有「补练昨天」的入口。
7. **存档写满时不报错、只静默丢。** `save()` 里 `QuotaExceededError` 没有单独分支，和 JSON 解析失败共用一个 `console.warn`；而且**所有调用方都忽略 `save()` 的返回值**。更糟的是 localStorage 写失败后 IndexedDB 镜像仍会写成功——于是**两份「保险」不是同一时刻的数据**，而恢复路径（`store.js:169-185`）只在 localStorage 解析失败时才看 IDB。我实测 90 天只有 496 KB（离 5 MB 很远，触发要 200 天以上或用户狂写对话/生词），但**一旦触发，用户看到的是一个正常的界面和悄悄停止增长的数据**。
8. **`log` 有 6000 条上限，超出时永久丢弃最老的 2000 条**（`store.js:349`）。按每天 20 题约第 200 天触发；被丢的正是最早的学习日，于是学情分析的 90 天窗口提前出现空档、streak 起点前移。导出 JSON 也一起少 2000 条，且没有提示。

### 期间｜一个能要了整站命的点

**更正：`Store.load()` 本身有 try/catch**（`store.js:110-120`），损坏的 JSON 会回退到默认档案——**不会整站白屏**，代价是静默丢数据。真正会被一条坏数据打死的是**数组元素级**：`log` 里混入一个 `null` 会让单词/学情/计划/弱点四个模块同时白屏；`cards[word] = null` 会让首页与单词页一起白屏；`daily` 里出现字符串会让学情分析的 SVG 报 `NaN`。`migrate()` 只保证「是数组 / 是对象」，从不校验元素。全站也**没有 `window.onerror` / `unhandledrejection` 兜底**（`main.js:1-96`）。

### 期间｜线上版（<演示服务器IP>）

- 首屏 gzip 880 KB，8 次 0.97–1.73 s，稳定；CSP/安全头齐全（好评）。
- `index.html` 是 `Cache-Control: no-cache` → **每次回访都要重下 880 KB**。手机流量下，一天开 3 次 ≈ 2.6 MB，一个月 ≈ 80 MB。
- `/api/health`：`llm: true`（模型 `nvidia/nemotron-3.5-super-vl:free`）、**`asr: false`**、`ocr: true`、`redis: false`、`tts: off`、音素通道 `rule`、知识追踪 `bkt`。也就是说云端**语音转写没通**，口语测评在手机上只能回落浏览器识别或手动输入；跑的是 free 档模型，长期用户的配额与稳定性都是未知数。
- 登录链路正常（demo 账号 200 / 0.12 s）。`GET /api/sync` 缺 `open_id` 时返回 422（契约是硬的，好评）。
- **PWA 的代价**：`deploy/sw.js` 把 `/` 和 `/index.html`（同一个 2.3 MB 文档）都列进 `PRECACHE` → 一次安装约 2.3 MB 进 Cache Storage；缓存名 `linguade-v6` 每次改版**新增一份全量副本且从不删旧**，实测本机已有 4 份版本共存（≈ 7 MB）。手机存储和首次安装流量都要算这笔账。

## 二、这一版最严重的 8 件事（按严重度）

### 1. 做完每日任务的那一刻，单词练习页卡死（P0，第 1 周必现）

`src/store.js:435`（出货产物 `dist/index.html:8600`）：

```js
if (q.items.every(it => it.done)) s._questsPerfect = 1;   // ← questProgress 的作用域里没有 s
```

`questProgress(rec)` 只声明了 `const q = Store.todayQuests()`，`s` 是**别的函数**的局部变量。所以当天 3 个任务全部完成的那一刻，这一行抛 `ReferenceError: s is not defined`，而它被 `logAnswer()` 调用——于是**之后每一次作答都必抛**。

我端到端复现了真实后果（脚本 `Temp/linguade-ux/quest_e2e.py`）：

```
答最后一题前：已学 0 / 20   任务：vocab 0/1 · speaking ✓ · reading ✓
点「轻松」后：已学 0 / 20   任务：vocab 1/1✓ …          报错：pageerror: s is not defined
再点一次：    已学 0 / 20                                报错：同上
连点 3 次：   全部 pageerror: s is not defined
```

用户看到的是：**我按了「轻松」，卡片不动。** 而 `src/modules/vocab.js:163-165` 的顺序是 `E().rate()` 先执行、`logAnswer()` 后抛错——所以那张卡**已经被评分了**（reps/EF/HLR 都写了），只是界面不前进；用户再点一次就是**同一词二次评分**，复习队列从这一刻开始被悄悄污染。进度条、回顾、今日数据、下一张卡全部不刷新。

两个连带后果：

- 依赖 `_questsPerfect` 的「任务大师」徽章（`dist/index.html:8706`）**永远不可能解锁**——赋值那行本身就抛错。
- **137 项测试全绿却带着它上线**。唯一涉及每日任务的测试 `tests/flow_v11.py::test_diagnose_does_not_feed_quests_or_xp` 断言的是「诊断**不该**推进任务」——它测的是相反方向，全流程没有任何一次把 3 个任务做完。**最活跃的用户（每天把任务清空的人）恰好是唯一没被覆盖的那条路径。**

修法是一个词：`Store.s._questsPerfect = 1`。但它值一个 P0，因为它杀死的正是产品最核心的那个循环。

### 2. 队列预算写死 20 张，导致 90 天后新词摄入归零（P0，产品级）

- 12px 下限：10+ 处 10–11.5px（见「期间｜手机上」）。守这条的测试**只量 10 个写死类名的假元素**（`tests/flow_v21.py::test_small_text_floor_12px`，把 `<span class="phon-note">x</span>` 之类插到 `left:-9999px` 再读 computed style），从不量真实页面——所以它绿，而页面照样 10px。

### 7. 同步会整档覆盖，且唯一的保护逻辑对新设备永久失效（P0，数据损失）

`store.js:653` 上行整个 `JSON.stringify(Store.s)`、`store.js:681` 下行整体 `set()`，**没有字段级合并**；唯一的保护是读 `s._snapAt` 的冲突提示，而恢复时 `_snapAt` 会被删掉（`store.js:661`）→ 换设备恢复后提示永不触发，直接覆盖云端。这两条合起来意味着：一个认真用两台设备的人，**一定会丢一边的数据**。（更正：`snapshot()` 删除整个 `cfg`，API Key 不上行。）

### 8. 时区一搬，连胜归零（P0，对这个产品的人群是必然事件）

`dayKey` 按「写入那一刻的时区偏移」把 UTC 折成日期（`store.js:146-149`）。用户从国内出发到德国，系统时区 +8 → +1，`today()` 立刻算出一个未来日期，`daily` 全是过去日 → `streak()` 归零、横幅消失、徽章与每日任务集体错位。对一个叫「留德学习陪伴」的产品，**换时区不是边缘 case，是产品的主线剧情**。

## 六、给不同的人

- **B1/B2 冲刺者（最该用它的）**：单词 + 错题本 + 模考依然是最值三件套，调度和诚实标注是真本事。但**把每日队列容量当成设置项去调**（现在做不到，只能等 P0-1），并且**别相信机器词表的中文释义直接写进作文**——`Krokodil C1`、`Sprecher 扬声器`、`Eisbär 白熊` 都还在队列里。
- **A1/A2 初学者**：A1/A2 的人工册（lexicon-1..8）例句覆盖 100%，是最好的部分；一旦进入 lexicon-9/10 的机器词，一半没例句、错义率最高。建议先用人工册，机器词只当查词。
- **老师/机构**：多设备合并仍没有（只有冲突提示），内容审核、班级、进度分发全无；**别直接发给学生**，尤其别在例句红线补上之前。
- **答辩演示**：`file://` 双击 → 点「一键导入」→ 讲「今天学什么」→ 打开「今天为什么练这 30 个词」→ 词卡点「报错」→ 沙盘看四方对比。**但别现场注入长期数据**：一注入就会看到 877 个濒危、0 个新词、3.7 万像素的错题本。
