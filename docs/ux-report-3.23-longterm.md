# LinguaDE 长期使用报告（3.23.x，2026-11-07）

## 0. 这份报告怎么来的

我没有真的用了两个月。我用的方法是在真实 Chromium 里跑当前源码版（`index.html`），按四个时间点注入学习档案，然后逐页操作、截图和测量。

- **第 1 天**：全新档案。真实做完 10 题诊断，真实刷完第一轮 8 张词卡。
- **第 1 周**：注入 7 天连续学习、140 张词卡、22 条错题。
- **第 2 个月**：注入 60 天（约 18% 的天数缺勤）、820 张词卡、160 条错题、2 次模考，距考试 19 天。
- **断学 9 天回来**：在第 2 个月档案的基础上，把全部记录整体前移 9 天。

每个时间点都在 1440 和 390 两个宽度下打开全部 19 个页面。脚本在 `.ux-sim/sim.py`，截图在 `.ux-sim/shots/`，数据在 `.ux-sim/metrics.json`。

用户画像设定为"小林"：备考 TestDaF，B1 左右，每天 30 分钟，主要用 Windows 笔记本，通勤时用手机。

**没测到的部分**：
- 真实录音与口语评分、ASR、大模型对话质量、拍照批改、云同步、暗色模式。
- 真实的德语语音：无头浏览器没有德语语音包。
- "注入"档案不等于真实的时间流逝。积压数字会受我造的数据影响，所以第 3.1 节的根因是直接用引擎常数算的，不依赖造数。

全部运行中 console 错误为 0。首屏 214 ms（源码版）；单文件版用 file:// 冷启动 134 ms。

## 1. 时间线：一个用户的真实感受

### 第 1 天：第一印象不错，但第一项任务就有点乱

- **诊断页**很干净：一题一屏，选完立刻给出解析，10 题大约 3 分钟。几处小别扭：
  - 还没开始学，右上角就已经挂着"🔥0 天"和"Lv.1 · 0 XP"。
  - "完成诊断后解锁"这句话在侧栏和正文里各出现一次。
  - 页面右半边是空的。
- **诊断结果**：正确率 30%，判定 A1，建议每天 25 分钟。结果页诚实地写了"不代表完整 CEFR 认证"，这点我很认可。但今天的计划是：

  > 词汇练习 8 张（到期优先）→ 阅读理解 1 篇（限时）→ 新词 15 个＋复习

  有两条都是背词。刚测出 A1，第一天就排"限时阅读"，有点劝退。原因是诊断出的薄弱项是"阅读、词汇"，而 `makePlan` 每天固定排一条词汇任务，薄弱项里的"词汇"又排了一次。
- **单词卡**是整个产品里做得最好的地方：
  - 大号衬线词头，冠词按词性着色。
  - 有"入队原因"，有"人工编写 / AI 辅助"的可信标签，还能一键报错。
  - 问题是词头上方叠了 3 行元信息（等级·词性·新词·可信标签·报错 / 入队原因），刚上手时视线不知道该落在哪。
- **刷完 8 张以后**：
  - 页面出现了"完成词汇任务"回执，但我没点。回到首页，显示"已标记完成 0 项"。我明明刚做完，还得再确认一次。
  - 我给 2 张卡点了"完全不会/很吃力"，它们立刻进了错题本。首页显示"2 条未掌握错题"。第一天就有错题，感觉自己被记了过。
  - 首页已经弹出"学习数据备份提醒"。我才学了 3 分钟。
- **小瑕疵**：`Computer` 的音标显示为 `/kɔmpuːte/`。旁边虽然标了"规则推导，非词典标音"，但外来词按德语规则推导出来就是错的。

### 第 1 周：节奏建立起来了，但数字开始让人不安

- 连胜 7 天，等级到 Lv.6，已经拿到 7 枚徽章。正反馈来得很快。
- 学了 140 个词，首页最大的数字是 **"113 待复习"**，单词页还写着"96 个今天排不下"。才第一周，就感觉永远还不完。
- **错题本**的筛选标签直接显示内部字段名"vocab · 12""grammar · 6"。每一条错题都同时挂着"单词"和"vocab"两个标签。
- **刷卡效率**：空格能翻面，但四个评分按钮是 `<div>`。它们不能 Tab 聚焦，也没有 1–4 数字快捷键。每张卡都得挪鼠标去点，一天 25 张、一周近 200 次。对于高频刷卡的人，这是最磨人的一点。

### 第 2 个月：系统越用越"重"

- **复习积压失控**：820 张卡，首页写着"785 待复习"，而每天预算只有 25 张。同一个概念，在不同页面显示成 4 个不同的数字：

  | 位置 | 显示 |
  |---|---|
  | 首页大字 | 785 待复习（含濒临遗忘） |
  | 单词页标题行 | 到期复习 623 个 |
  | 单词页说明 | 另有 768 个到期词今天排不下 |
  | 单词页侧栏 / 学情分析 | 待复习 623 · 濒临遗忘 785 |

  作为用户，我分不清哪个才是"我欠的"，最后干脆不看了。
- **等级封顶**：Lv.10 的门槛是 5600 XP，我已经有 14200 XP，经验条一直停在"已满级"。按每天约 40 题、每题 10 XP 计算，两周左右就能满级。后面 6 周，XP 这套激励就没有作用了。
- **学情分析趋势图**：
  - 没学的日子和"今天还没学"都按 0% 正确率画。每天早上打开，曲线最右端都是一个跌到 0 的悬崖。
  - 头几天没数据，也画成了 0。
- **考前 19 天**：
  - 考试卡写着"剩余 19 天约能过 8% 的词库"。数字是诚实的，但卡上除了"调整考试日期"没有任何可做的事，只剩焦虑。
  - 今天的任务是"词汇 10 张 + 影子跟读 + 跟读评分"。冲刺期没有任何一条模考任务：`makePlan` 的任务池里本来就没有模考。
- **听力页和错题本**：一进页面就弹 toast，"这台设备没有安装德语语音，发音不可用"。我并没有点发音。中文 Windows 默认不带德语语音包，目标用户里有相当一部分人每次都会看到这条提示，而且听力练习除了 80 条真人录音外基本不可用。
- **计划页（手机）**：
  - 顶部显示"生成于 2026/11/7 13:10:47"，精确到秒，没有意义。
  - 第一张卡是"留德时间轴 · APS 审核 0/5"，和今天学什么无关。

### 断学 9 天回来：最需要被接住的时候，产品在"记账"

- 顶栏显示"🔥0 天"，而我之前最长连胜是 35 天。
- 其实存在 72 小时的"连胜复活"机制，但提示放在默认折叠的"更多数据与全部模块"里。首屏完全没有提。
- 手机上，"你已**隔日**未复习 —— 820 个词条的回忆概率低于阈值"这条横幅排在今日任务列表**下面**。
  - 我断了 9 天，不是"隔日"。
  - 横幅上的按钮叫"开始今天的队列"，首屏主按钮叫"开始今日倒排任务"，两个 CTA 抢同一件事。
- 下面还叠着备份提醒和考试倒计时。回来的第一屏是三块提醒，全是在提醒我欠了什么。

## 3. 根因与证据

### 3.1 为什么复习永远做不完（结构问题，与造数无关）

HLR 的增长系数是 `growOk 1.9`（前 2 次）和 `growLate 1.35`，阈值 `retention 0.9`（`src/engine.js`）。只要回忆概率低于 90% 就算到期。

到期间隔 = h × log2(1/0.9) ≈ 0.152 h，按引擎常数算：

| 连续答对次数 | 半衰期 h（天） | 再次到期（天） |
|---|---|---|
| 3 | 4.9 | 0.7 |
| 5 | 8.9 | 1.4 |
| 10 | 39.8 | 6.1 |
| 15 | 178.6 | 27.1 |

一个词要连续答对 10 次，才能一周不出现。学过 800 个词的人，每天理论上要复习 100 张以上，而预算是 25 张。所以"待复习"在任何真实使用中都会单调上涨。

### 3.2 其他代码定位

- **评分键盘**：评分按钮是 `src/modules/vocab.js:192-197` 的 `<div class="rate-btn">`。`src/core/ui.js:425` 只处理空格翻面。
- **自评进错题本**：`vocab.js` 里 `if (!ok) Store.addWrong(...)`。
- **两条词汇任务**：`makePlan` 先固定排一条 `vocabTask`，薄弱项 `focus` 里的"vocab"又排了一次。
- **等级封顶**：`Store.LEVELS` 只有 10 档，最高 5600。
- **复活提示**：`reviveHint` 只在 `#homeMore` 折叠区里渲染（`src/core/router.js`）。

## 4. 问题清单与改法

### High（影响每天的使用）

| Before | After | Why |
|---|---|---|
| 首页大字"785 待复习"，四处数字不一致 | 首屏只给一个数："今天 25 张，约 30 分钟"。积压放进二级信息，全站共用一个 `todayLoad()` | 用户只需要知道今天做什么。同一概念出现四个数字，会让人对整个系统失去信任 |
| 90% 阈值配合 1.35 的增长，导致积压线性膨胀 | 把沙盘里已有的 FSRS 接到正式调度；或者调高 `growLate` / 把阈值降到 0.85，并用 3.1 节的表重新验算 | 这是问题的根源，只改 UI 治标不治本 |
| 评分只能用鼠标点 `div` | 改成 `<button>`，加 1–4 快捷键，按钮上显示键位 | 高频动作的效率决定用户能坚持多久 |
| 刷完一轮还要手动"完成词汇任务" | 达到 `spec.minAnswered` 就自动勾选，回执改成"已完成 ✓，可撤销" | 证据已经采集到了，再让用户确认一次是纯负担 |
| 断学回来是三块提醒加"0 天" | 断学 ≥2 天时，首屏换成回归模式："欢迎回来，先做 15 分钟恢复包"，并把复活倒计时放进首屏。横幅合并成一条，文案按天数写（不再说"隔日"） | 回归是流失风险最高的时刻 |

### Medium（用久了会烦）

| Before | After | Why |
|---|---|---|
| 自评"不会"进错题本 | 词卡的"不会"只影响调度，或者单独放进"难词"列表，不算错题 | 错题本应该记录真实的答错，不应该被自评灌水 |
| 错题本显示"vocab · 85"，每条挂双标签 | 只显示中文分类、一个标签；列表压缩成单行 | 内部字段不应该外露 |
| 趋势图把无数据画成 0% | 无数据的日子断线或画成虚线，"今天"不画点 | 现在每天早上都会看到一个假的暴跌 |
| Lv.10 / 5600 XP 封顶 | 延长等级曲线，或者满级后换成"周 XP / 赛季"作为目标 | 两周满级后激励就失效了 |
| 一天排两条词汇任务；A1 第一天就排限时阅读 | `focus` 里去掉 vocab，换成次薄弱项；A1/A2 用不限时阅读 | 第一天的体验决定用户会不会回来 |
| 冲刺期没有模考任务 | 距考 ≤30 天时，每周插入一次分项模考 | 备考产品的冲刺期，核心就是模考 |
| 进听力页和错题本就弹"未安装德语语音" | 只在用户点发音时提示一次，同时给出安装指引；听力题优先用真人录音或后端 TTS | 中文 Windows 的用户每次都会撞上这条提示 |
| 免责小字遍布各页 | 每页最多一句；可信说明统一收进"数据与可信度"浮层 | 说明太多，用户就一句都不读了 |

### Polish

| Before | After | Why |
|---|---|---|
| 每屏挂着比赛标语和"模块就绪度" | 只在"关于"页显示 | 这些是给评委看的，不是给学习者看的 |
| 诊断前就显示 0 天 / Lv.1；锁定说明出现两次 | 诊断完成前隐藏游戏化芯片；锁定说明只保留一处 | 第一印象 |
| 第 1 天就提醒备份 | 累计学习 ≥3 天或 ≥50 条作答后再提醒 | 太早提醒会被当成噪音 |
| 计划页"生成于 …13:10:47"，顶部是 APS 时间轴 | 时间只显示到"今天"；时间轴移到计划页底部或单独页签 | 计划页应该聚焦计划 |
| 外来词按规则推导出错误音标 | 加外来词例外表；没把握时不显示音标 | 显示错的音标比不显示更糟 |
| 词卡上方 3 行元信息 | 只保留"等级 · 新/复习"；可信标签和入队原因收进 ⓘ | 视线应该先落在词头上 |

## 5. 建议的升级顺序

1. **第一轮（1 周）**：调度换成 FSRS 或调参，全站统一负担数字，评分支持键盘，任务自动完成。这四项做完，日常体验的变化最大。
2. **第二轮（1 周）**：首页回归模式，复活提示前置，错题本去噪，趋势图修正，计划去重并加入模考。
3. **第三轮**：精简文案与小字，移除比赛元素，延长等级曲线，修 TTS 提示和外来词音标。之后用 `.ux-sim/sim.py` 重跑四个时间点，拿前后截图对比。

## 6. 整改状态（3.24.0，2026-11-07）

报告第 4 节的条目已全部改完，见 CHANGELOG 3.24.0。验收方式：

- 浏览器逐条核对：`.ux-sim/verify.py`，改后截图在 `.ux-sim/shots-after/`。
- 全量回归 254 passed；`tools/check.py` 与 `tools/smoke.mjs` 通过；`dist/index.html` 已重新打包。

| 条目 | 改后实测 |
|---|---|
| 四处待复习数字不一致 | 首页、单词页、计划页都是 785（同一档案） |
| 首页大字是积压 | 首页主数字是「25 · 今天的词卡」，积压以「另有 768 个排在之后」小字显示 |
| 评分只能点鼠标 | 评分是 `BUTTON`；空格加 1–4 键刷完一轮 |
| 刷完要手动确认 | 本轮结束时任务已标记完成，带「撤销完成」 |
| 新词「不会」进错题本 | 首日刷 8 张、2 张选「完全不会」后，错题数为 0 |
| 一天两条词汇、A1 限时阅读 | A1 首日计划：词汇 8 张 → 阅读理解 1 篇 → 句法纠错 8 句 |
| 冲刺期无模考 | 距考 20 天的 7 天计划里有 1 天包含全真模考 |
| Lv.10 封顶 | 14,200 XP 显示 Lv.14（42%） |
| 断学回来三块提醒 | 显示「欢迎回来」，有复活提示和「先做 10 张」，横幅 0 条 |
| 趋势图假 0% | 14 天里只画有作答的 10 个点 |
| 错题本 `vocab · 85` | 不再出现英文类型名 |

**仍是推算或未覆盖的部分**：

- **积压能否真正收敛**：HLR 新常数下，答对 1 / 2 / 3 / 5 次后的再次到期间隔约为 1.0 / 1.9 / 3.8 / 15 天，这是按引擎公式算的。验收用的是注入档案，不是真实时间流逝，所以积压会不会收敛还要等真实使用数据。
- **老用户迁移**：老用户的半衰期迁移时一次性 ×3.5。这对积压的实际下降幅度没有实测。
- **未测**：暗色模式、真实德语语音、录音、云同步。
